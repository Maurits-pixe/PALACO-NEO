# NEO-017 — Recovery evidence receipts and conflicting-observation checks (DRAFT)

This verification-only module accepts an independently trusted review-ledger before position, a pre-write proposed entry and a current ledger snapshot. It verifies the chain, anchored pre-write prefix and exact appended proposal; then produces an **unsigned, deterministic SHA-256 evidence receipt** for COMMITTED or NOT_COMMITTED states. It compares two receipts and refuses to label mismatched observations stable.

## Limitations
- The digest is a checksum, **not a digital signature or independently stored anchor**; any party controlling the receipt can recompute it. It is not an attestation of trustworthy storage, durability, timestamp, review authorization or caller identity.
- A NOT_COMMITTED snapshot and a later COMMITTED snapshot can be a legitimate sequence; this conservative comparator reports HOLD until a consistent new observation is independently assessed.
- Only snapshots and pre-write proposals from separately authenticated custody are meaningful. Multiple observations from a compromised storage source are not independent evidence.
- No automatic retry, external storage, background work, lock recovery, merge or production release. GO-13 HOLD and authorization DENY remain active.

Run `npm test` in Node >=20. Security review needed before extending this prototype.
