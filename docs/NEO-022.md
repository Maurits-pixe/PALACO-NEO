# NEO-022 — External compare-and-swap receipt protocol (DRAFT)

## Exports
- `prepareAnchorCAS(plan, observedRegistry, externalAnchor, operationId)`: creates a request **only** if NEO-021 classifies the locally consumed challenge as PENDING_ANCHOR_CAS and the external anchor remains at the trusted BEFORE state.
- `anchorCASPayload(cas)` and `anchorCASSigningPayload(cas, custodianId)`: domain-separated, canonical signing bytes bound to namespace, operation ID, plan digest, before/after anchors, outcome and custodian.
- `verifyAnchorCASReceipt(plan, receipt, trust)`: validates a custodian's Ed25519 signature against independently trusted signer key/status, expected unique operation ID and before-anchor, and the complete proposed transition.

## Security boundary
No external custodian is contacted, no anchor is modified, and no transaction is executed by this module. `APPLIED` is a **signed assertion from an external custodian**, not proof that external storage committed durably or atomically. The external custodian must independently authenticate and verify the complete plan, the challenge's provenance, and the current anchor, then enforce atomic compare-and-swap and durable one-time operation IDs. The caller must externally verify the resulting anchor and advance the independently trusted floor.

The plan digest covers immutable transition identifiers and anchors but does not authenticate the proposedRegistry object in isolation. The relevant digest is in `after.digest`, so consumers must validate that proposedRegistry matches it using NEO-021; the custodian must not trust a supplied hash without verifying its source.

A replay may still verify if the caller reuses the same expectedOperationId and trustedBefore. This module cannot provide durable replay prevention or independent key custody. Every return has `authorized:false`. GO-13 HOLD, DENY; no merge or production release.
