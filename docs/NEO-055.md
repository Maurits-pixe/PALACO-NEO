# NEO-055 — Independent witnessed incident checkpoint succession (DRAFT)

## Built
- `incidentCheckpointPayload`: domain-separated Ed25519 message binding namespace, unique checkpoint ID, sequence, predecessor checkpoint hash, exact verified NEO-054 incident register count/head and custodian identity.
- `incidentCheckpointHash`: canonical SHA-256 commitment to the exact signed checkpoint and 2–16 custodian attestations, invariant under signature-array ordering.
- `verifyIncidentCheckpointHistory`: re-verifies the **entire original NEO-054 signed incident journal** at every checkpoint, including its original NEO-053 receipt checkpoints, NEO-052/051 transfers and underlying NEO-050/049/048/... evidence. Requires two or more different ACTIVE checkpoint custodians and Ed25519 signing keys distinct from NEO-054 OWNER/SECURITY reviewers and original disputed/NEO-053 checkpoint custodians. Rejects duplicate IDs, shared keys, reassignment of signing keys across historical identities, unexplained key rotation, forged/missing attestations, broken checkpoint hash succession and upstream incident register truncation or prefix rewriting. A separately authenticated monotonic `{count,head}` floor detects checkpoint rollback and forks.
- `inspectIncidentCheckpointConflict`: verifies two incompatible Ed25519 incident-register assertions from the **same pinned custodian key**, for exactly the same checkpoint ID, namespace, sequence and predecessor, and constructs a stable conflict digest. Neither branch is promoted to canonical truth; no operational decision is issued.
- Twenty-four regression tests exercise valid one-/two-checkpoint succession, independent externally pinned floors, original archival-byte and OWNER-review forgery, missing or duplicated witnesses, revoked/key-reused/rotated custodians, hash corruption, rollback, and signed/forged conflicting statements.

## Security limitations
This code is a **read-only evidence verifier**. It does not send alerts, create or persist a durable audit log, issue signatures, remove accounts, close incidents, grant permissions, deploy any service or execute an operational emergency response. Distinct signing keys do not alone prove independent physical or organizational custody. Its cryptographic assertions rely on full authentic source histories and externally secured trust roots and monotonic register pins. Without those independently retained anchors, deletion or wholesale replacement of the supplied log can go undetected.

An empty log verified from a genesis pin is not evidence of no prior incidents. Signed contradiction is evidence of a cryptographic inconsistency, not proof of which external account or storage state is real. NEO-055 intentionally has no permission to close, resolve or release incidents.

Every result sets `authorized:false`; GO-13 HOLD/DENY. No merge or production deployment.
