# NEO-038 — Dual-witness signed repair checkpoints (DRAFT)

NEO-038 verifies a **full NEO-037 repair evidence bundle from original bytes and signatures**, then independently verifies a checkpoint signed by two witness keys distinct from each other, every reviewer key and the supplied replica keys.

## Implemented
- `recoveryPostEvidenceDigest`: domain-separated SHA-256 binding the verified recovery context, exact reviewer signatures, original post-observation signatures, IDs and per-artifact encoded-byte hashes. The digest is an identity for supplied evidence, not physical storage proof.
- `repairCheckpointPayload` and `repairCheckpointHash`: distinct signing and chain-entry domains, binding recovery ID, proposal hash, inventory hash, custody-lineage position, previous checkpoint count/head, post-evidence digest and witness ID.
- `verifyRepairCheckpoint` reruns NEO-037 with supplied original inputs; checks an externally retained checkpoint before-position, verified recovery context, two externally pinned ACTIVE Ed25519 witness keys (not shared with reviewer/replica keys), exact expected witness roster and signed checkpoint digest. An optional externally pinned next position rejects forks and rollback.
- Nineteen regression tests cover valid signed evidence, changed original bytes, fake reviews, missing/duplicate witnesses, key aliasing, revoked witness, forged signatures, stale pins and modified chain hashes.

## Security and authorization limits
This code creates no new checkpoint, signs no material, persists no floors and performs no repair. A sequence count and previous head only provide *local structural* replay resistance. Durable monotonic checkpoint storage and globally unique checkpoint IDs must be enforced by independent external custody. A verified signature is a witness assertion, not attestation of independently audited durable remote storage. An attacker controlling all supplied trust pins, post-state and keys can fabricate apparent evidence. There is no trusted time, hardware attestation, durable identity tracking, physical replica independence or verified external synchronization.

The verification result always carries `authorized:false`; it cannot release the case or GO-13. No merge, live repair, deployment, publication or automatic execution.
