# NEO-034 — Signed escalation case custody and transfer evidence (DRAFT)

## Implemented
- `verifyCaseHandoff` re-verifies the **complete** NEO-033 escalation journal with its original NEO-032 signed forensic dossiers, separately trusted witness keys and pinned journal floor.
- `caseHandoffPayload` binds OWNER and SECURITY Ed25519 endorsements to case ID, dossier digest, journal count/head, source/destination custodians, unique transfer ID and pinned review-policy digest.
- `custodyReceiptPayload` binds an independently pinned destination custodian Ed25519 receipt to that same transfer and an explicit ACCEPTED outcome. REJECTED, revoked keys, mismatched destination IDs and forged signatures fail closed.
- `classifyCaseCustodyObservation` compares supplied claims without asserting independence or actual delivery. Even matching claims never return authorization.
- Seventeen tests cover genuine signatures, missing forensic evidence, revocation, incorrect journal floor, duplicate reviewers, mismatched custody signatures, replay context and conflicting observations.

## Security boundary
This is a **read-only evidence verifier**, not a durable custody service. The actual handoff process, delivery, physical storage and independently signed receipt retention do not exist in this module. The caller must authenticate the externally supplied policy pin, historical witness keys, journal floor and destination custodian key. A single signed destination ACCEPTED statement **does not prove file transfer or receipt of the original bytes**, even when NEO-033 fully revalidates available evidence.

The transfer ID is checked against a pinned expected ID but no persistent replay ledger exists. Human identity verification, legal custody, storage durability, independent network connectivity, authorization to close cases, and real two-party operational separation remain future gates. No automatic release from ESCALATED_HOLD.

All outcomes have `authorized:false`. GO-13 HOLD/DENY; no merge, public exposure, production deployment or external writes.
