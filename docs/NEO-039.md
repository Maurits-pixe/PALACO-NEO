# NEO-039 — Complete repair checkpoint histories and fork evidence (DRAFT)

## Built
- `verifyRepairCheckpointHistory` verifies **every original NEO-038 checkpoint** and replays full NEO-037 reviewer, replica signature and byte verification, starting at genesis. It requires exact predecessor chain positions, no missing checkpoints, one-use recovery IDs and checkpoint IDs and no duplicated signed post-repair observation ID across the supplied history.
- A separately pinned `{count,head}` floor rejects truncation and conflicting histories. The result remains `VERIFIED_HISTORY_ONLY` with `authorized:false`.
- `inspectRepairCheckpointFork` re-verifies both complete branch histories, finds the earliest disagreement and reports an evidence-only `FORK_EVIDENCE_HOLD` if two valid independently supplied checkpoint branches diverge after one common predecessor. Shared signing witnesses are identified only where both authenticated witness ID and pinned PEM key match. A longer valid prefix is not a fork.
- Eighteen regression tests cover complete chains, tampered full bytes, forged checkpoint signatures, rollback, forks, duplicated recovery IDs/checkpoint IDs/observation IDs and evidence-only fork classification.

## Trust boundaries
This module **does not** persist, transmit or witness checkpoint events or maintain a globally immutable replay database. It relies on separately authenticated floors, entire case evidence histories, reviewer policy pins and witness public keys supplied by callers. Two valid conflicting branches suggest signer-key equivocation where the same signing keys appear in both; they do not establish culpability or physical custody. There is no trusted time or atomic external storage operation. A malicious actor who controls all trust anchors can fabricate self-consistent chains.

The witness-list comparison detects exact same witness keys, not legal/operational independence. Different branch histories beyond a trusted floor must be compared before the floor is advanced. No automatic revocation or repair and no production authorization.

GO-13 HOLD/DENY. All results `authorized:false`, no merge or production deployment.
