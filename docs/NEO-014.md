# NEO-014 — Descriptor-bound state reading and conservative lock cleanup (DRAFT)

The review-ledger adapter now opens the state file with Node's `O_NOFOLLOW` flag and validates the **opened descriptor** rather than trusting a separate pathname `lstat` before reading. It refuses symbolic links, multi-linked regular files, invalid/oversized JSON and any failed integrity checks. Lock cleanup now uses a nonrecursive `rmdir` only when the current lock directory has the same device/inode as the directory created by the operation. An existing lock is never stolen.

## Security scope and exclusions
- This addresses a narrow file-open race in the review-ledger read path. It **does not** eliminate directory replacement races, hostile same-user processes, lock path swap attacks, rename/write target races, unsafe parent directories, or all filesystem TOCTOU risks. A different directory could reuse an inode; inode/device equality is not a cryptographic owner identity.
- `O_NOFOLLOW` support and behavior vary by platform. If platform support is uncertain, fail closed and verify on the deployment target. Directory `fsync` is likewise platform-dependent.
- The lock directory is cooperative single-host coordination, not a security boundary against hostile actors. Insecure directory ownership, network shares, filesystem tricks or untrusted callers remain unsupported.
- Independent pins for reviewer policy and ledger state remain mandatory. Supplying a trusted-looking pin with mutable keys is **not** authentication.
- No privileged execution, approval, key activation, automatic retry, lock breaking, merge or production deployment. GO-13 HOLD and authorization DENY remain mandatory.

Run `npm test` with Node >=20. Tests are regression coverage, not platform certification or fault injection under real crashes.
