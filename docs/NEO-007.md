# NEO-007 — Pinned key registry & revocation evaluation (DRAFT)

This release adds **read-only, offline** key-registry verification for signed checkpoint attestations.

## API
- `keyRegistryDigest(registry)`: canonical SHA-256 digest of the exact registry version, namespace, sorted key entries and status.
- `verifyRegistryAttestation(records, envelope, registry, options)`: verifies externally pinned registry digest, minimum version, selected Ed25519 key, revocation status, count-based validity interval, signed checkpoint, chain and ancestry from an independently pinned `trustedFloor` count/head.
- Every result includes `authorized:false`, including successful verification.

## Trust boundaries
The registry is a **supplied snapshot**, not a registry service. An attacker controlling both the snapshot and its expected digest defeats this check. Pin and distribute the digest and floor through **independent authenticated custody**. This implementation does not issue keys, sign records, rotate keys automatically, obtain trusted time or propagate revocations. A revoked key is denied even for earlier attestations (conservative policy).

The validity window is based on audit count, **not wall time**. Rotation/revocation policy needs separate governance. A trusted floor of zero alone cannot prevent replay of old valid signed histories. Use a securely maintained floor head and count to prevent forks/rollback. No production approval, no release, no merge; GO-13 remains HOLD.
