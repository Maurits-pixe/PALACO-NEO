# NEO-025 — Revision-scoped custodian key epochs and rotation proposals (DRAFT)

## Implemented
- `custodianKeyHistoryDigest`: canonical SHA-256 over a full, immutable-in-context key epoch history (namespace, version, custodian IDs, Ed25519 public keys, inclusive start/exclusive end revisions, and status). Rejects overlapping periods, duplicate open-ended periods, malformed keys, and unbounded data.
- `proposeCustodianKeyRotation`: creates a non-authorizing, version-incrementing transition from an open trusted key epoch into a successor key at an explicitly supplied cutover revision. The old key remains verifiable only for earlier externally authenticated anchor revisions.
- `verifyHistoricalCASArchive`: checks a separately pinned version/digest and NEO-023 proof-chain floor, then re-verifies each original NEO-022 Ed25519 CAS receipt using the single key epoch selected by its CAS `before.revision`. Historical records of a compromised epoch are conservatively rejected.
- Thirteen tests: pinned-history integrity, rotation boundaries, old/new key substitution, compromise, overlaps, replay of stale pins, rollback and malformed material.

## Critical security distinctions
An external CAS anchor *revision* is **not time**. This implementation cannot establish when a signature was made or whether a key was trusted at that wall-clock moment. The history's cutover revisions, key status, version and pin MUST be established and authenticated outside this repo; a mutable file with its own hash is not independent custody. It is unsafe to infer historical validity from untrusted key-epoch metadata.

Rotation proposals are not durable, signed governance events or an authoritative issuance flow. There is no historic key-epoch chain, revocation effective timestamp, globally atomic cross-custody transaction, independent cryptographic time, signed receipt storage or automatic deployment. Same-key-overlap and a previous key's compromise require a separate reviewed revocation policy. No merge/release/production authorization. GO-13 HOLD / DENY; all successful results have `authorized:false`.
