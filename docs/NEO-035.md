# NEO-035 — Case custody lineage, byte inventory and recovery (DRAFT)

## Implemented
- `verifyCustodyLineage` checks every transfer through the original NEO-034 OWNER+SECURITY-reviewed handoff, which replays the full NEO-033 journal and NEO-032 forensic signatures. New transfers must start at the previous destination, preserve case identity and use a globally unique ID within the supplied chain. A separately pinned position detects truncation and forks.
- `transferInventoryDigest` validates a bounded, duplicate-free artifact manifest. The verifier checks the supplied **full bytes** for every manifest entry (canonical base64, SHA-256 and byte length, up to 64 artifacts of 1 MiB each). Reordered artifacts hash equivalently. Unaccounted, altered or absent artifacts fail closed.
- `transferStoragePayload` binds destination custodian, transfer ID, case, prior lineage hash, signed handoff evidence digest and inventory digest. A missing, rejected or invalid destination-signed OBSERVED storage claim results in HOLD; there is no silent retry. Inventory changes between transfers are refused.
- Sixteen new regression tests cover valid one- and two-hop lineage, replay, missing bytes, altered manifests, forged destination signatures, unsupported inventory mutation and rollback.

## Security boundary
The storage receipt is a **signed assertion** of the destination custodian. It is not an independently observed, durable storage proof. The verifier sees caller-supplied bytes, not guaranteed bytes in a remote or offline vault. A proof of receipt of original bytes does not prove physical retention, replication, legal custody or freshness. There is no disk writer, network transfer, trusted clock, durable anti-replay service, protected original archive or automatic recovery.

The initial trusted lineage floor, complete forensic/journal inputs and Ed25519 custodian keys MUST be authenticated separately. If a party can rewrite the trusted floor, it can fabricate its own apparent history. Verified results are only `VERIFIED_ASSERTIONS_ONLY`, always `authorized:false`.
