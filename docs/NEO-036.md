# NEO-036 — Replica inventory verification and repair planning (DRAFT)

## Implemented
- `replicaObservationPayload`: domain-separated Ed25519 signature bytes binding namespace, case, independently pinned NEO-035 inventory digest, custody-lineage count/head, replica identity, unique observation ID and PRESENT/INCOMPLETE status.
- `assessReplicaArchive`: examines a bounded full-byte inventory supplied by 2–16 replicas and their separately trusted public keys. Each supplied artifact is verified by canonical base64, exact byte length and SHA-256 against a separately pinned NEO-035 manifest. Rejects unlisted/duplicate artifacts, modified bytes, forged signatures, revoked replica keys, duplicate signing keys and reused observation IDs.
- If all supplied replicas are complete, output is `VERIFIED_ASSERTIONS_ONLY`. If at least two independently keyed replicas contain the full matching inventory but a third lacks artifacts, the function returns an **offline, read-only** `REPAIR_PROPOSAL_ONLY` listing missing artifact IDs and defective replica IDs. Fewer than two complete sources, contradictory signed claims or corrupt bytes remain HOLD.
- Seventeen regression tests cover complete replicas, degraded replicas, omissions, forgeries, duplicate keys/identifiers, false completeness, pinned namespace, corrupted bytes and inventory changes.

## Security and operational boundary
Two separately signed replicas do not prove the storage providers are physically or operationally independent. This code does not fetch remote bytes, authenticate freshness, issue repair instructions to external systems, write files, prove storage durability, or recover missing contents. The external operator must authenticate the **manifest pin, lineage position, trusted replica registry, and available byte sources** before relying on any assessment. Distinct Ed25519 keys are a necessary but not sufficient independence check.

An INCOMPLETE claim with missing bytes can be consistent with a degradation; a mismatching present file is treated as corruption and HOLD, not automatically overwritten. A signed PRESENT statement cannot replace actual full-byte verification. Observation IDs are only checked within a caller-supplied assessment; there is no durable replay store.
