# NEO-033 — Signed forensic escalation journal (DRAFT)

## Implemented
- `verifyEscalationJournal` checks original NEO-032 signed equivocation dossiers against externally authenticated witness trust, plus version-pinned NEO-027 reviewer policy, Ed25519 OWNER and SECURITY signatures, sequential hash-chain linkage and independent rollback floor.
- `escalationReviewPayload` signs the precise case ID, action, forensic dossier hash, predecessor and review-policy digest with a role-specific signing domain.
- `escalationEntryHash` deterministically commits the whole dual-signed journal entry.
- Supported actions are `OPEN` and `REVIEWED_HOLD`. Duplicate openings, unmatched reviews, missing evidence, revoked reviewers, forged signatures, forks and rollback fail closed.
- All cases remain `ESCALATED_HOLD` regardless of reviewed status. **No closure, release, revocation or execution code exists.**
- Sixteen regression tests cover these invariants.

## Security and operational boundary
The registry is a read-only verifier over caller-supplied entries and forensic evidence; it neither persists entries nor authenticates the externally supplied policy pin, witness key history or checkpoint floor. These inputs require separate trusted custody and an authenticated, durable journal implementation before any operational use.

A pair of valid reviewer signatures confirms statements by two private keys, not the reviewer's real-world identity or legal authorization. A verified witness conflict is evidence of contradictory signatures under a pinned key, not proof of wrongdoing. Historical revocation timing and forensic preservation policies are unresolved.

GO-13 HOLD/DENY. Every result has `authorized:false`. No merge, production rollout, auto-closing of cases, external write or notification.
