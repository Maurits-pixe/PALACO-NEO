# NEO-053 — Independently signed receipt succession checkpoints (DRAFT)

## Implemented
- `receiptCheckpointPayload`: domain-separated Ed25519 payload binding one receipt-history count/head, the checkpoint ID and sequence, namespace, predecessor checkpoint hash, and the custodian identity.
- `receiptCheckpointHash`: deterministic SHA-256 commitment to the signed checkpoint with 2–16 separately identified custodian attestations; witness array order does not affect the commitment.
- `verifyReceiptCheckpointHistory`: replays the **complete NEO-052 receipt succession chain and every original NEO-051 transfer, NEO-050 escalation checkpoint, NEO-049 incident and underlying archival evidence** for every checkpoint. It refuses missing, forged, revoked or duplicated witnesses, shared signing keys, reuse of original archiving-recipient or escalation-custodian keys, unreviewed public-key changes for a continuing custodian ID, and reassigning a key to another custodian ID. It ensures append-only continuity of previous receipt entry hashes across checkpoint upgrades and detects rollback or fork relative to a separately retained external checkpoint floor.
- `inspectReceiptCheckpointEquivocation`: verifies two contradictory, domain-separated Ed25519 claims from the **same pinned custodian public key** for one namespace, checkpoint ID, sequence and predecessor. The function returns `RECEIPT_CHECKPOINT_EQUIVOCATION_HOLD` with an SHA-256 conflict fingerprint, without determining a canonical historical truth.
- Twenty-five regression cases cover valid single/two-checkpoint succession, signature forgery, missing/revoked/duplicate witnesses, cross-role key reuse, underlying original receipt and archival byte corruption, checkpoint key continuity, rollback, external pin conflicts, and signed/forged equivocation.

## Limits
The checkpoint is a read-only verifier: it creates no signature, does not transfer bytes, store records, contact real archival institutions, grant permission, close conflicts or distribute keys. A cryptographically valid signature shows a statement by a signing key; it does **not** prove real-world independent physical custody or organizational independence. External trusted public-key rosters, full original evidence and monotonically retained checkpoint floor pins remain essential to resist deletion and substitution. An empty checkpoint history verified against genesis does not establish there were no other histories.

NEO-053 does not implement receipt-key rotation, real-time notifications, adjudication or an external secure archival service. All results are `authorized:false`. GO-13 HOLD/DENY; no merge, release or production deployment.
