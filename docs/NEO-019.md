# NEO-019 — One-time recovery challenge register (DRAFT)

## Added
- Deterministic SHA-256 register digest with unique 256-bit challenge identifiers and ISSUED/CONSUMED statuses.
- Pure `proposeChallengeConsumption`: rejects unknown, consumed or signer-mismatched challenges and checks the Ed25519 recovery attestation from NEO-018.
- Cooperative single-host local adapter `consumeRecoveryChallenge`: verifies the caller's externally pinned register digest while holding a mkdir-based lock; verifies the challenge and signature; writes a replacement snapshot via exclusive temp file, file fsync, rename and directory fsync. `inspectChallengeRegister` is read-only.
- No register creation or challenge issuance API. The externally provisioned register must already exist on disk.

## Trust limits
This is **not** an independent or authoritative challenge service. The trusted digest and signer trust MUST be authenticated and stored in separate trusted custody. If the current register and its digest can both be rolled back, a previously consumed challenge can be replayed. Callers must independently advance their pinned digest after success and reconcile uncertain commits before any retry.

Only cooperative local writers are coordinated. Same-user adversarial processes, process crashes, inode reuse, directory swaps, Windows fsync differences and external multi-host storage are not solved. Missing register fails closed. No automatic lock stealing, authorization, key issuance, merge or production deployment; GO-13 HOLD, DENY.

Run `npm test` with Node >=20.
