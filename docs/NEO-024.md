# NEO-024 — Full signed CAS receipt archive verification (DRAFT)

## Changes
- `custodianKeySnapshotDigest(snapshot)` checks and hashes an explicit custodian verification-key snapshot, including signer ID, status, public key, version and namespace. The digest **must be pinned outside the archive**.
- `verifyCASProofArchive(entries,archive,trustedFloor,keySnapshot,keyPin)` reconstructs the entire NEO-023 CAS proof chain, checks the independently retained count/head floor and re-verifies **each original signed NEO-022 CAS receipt** with the pinned key snapshot. It compares recomputed proof entries byte-for-byte in canonical object layout with the archived ledger entries.
- Every archive item retains `{plan,receipt}`; the archive does not accept a caller-supplied verification key in a receipt.
- 11 regression tests cover signature forgery, archival mismatch, revoked/unknown keys, tampered pins, missing receipts and rollback.

## Trust and historical key status
This is a **read-only prototype**. The snapshot is not an actual historical key registry and lacks trusted signing-time and revocation-effective-period evidence. It treats a signer marked REVOKED in the supplied pinned snapshot as invalid even for past receipts. Production historical validation requires independently authenticated key-epoch history, trusted revocation semantics and a documented policy for legacy signatures. Never silently reinterpret the current key status as a complete historical proof.

This module **does not store** the archive or its key snapshots, verify the physical separation of custodians, prove atomicity/durability of the CAS, or independently authenticate a key pin. The external trust floor and signer snapshot MUST originate from authenticated independent custody. No merge, deployment, automatic retry, approval, key activation or external writes. All outputs remain `authorized:false` under GO-13 HOLD / DENY.

Run `npm test` on Node >=20 and require independent security review.
