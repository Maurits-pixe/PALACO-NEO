# NEO-063 — Independently witnessed receipt-incident transfer checkpoints (DRAFT)

## Implemented
- `receiptIncidentTransferCheckpointPayload`: domain-separated Ed25519 statement binding the exact NEO-062 receipt register position (count/head), namespace, unique checkpoint ID, checkpoint sequence, predecessor checkpoint SHA-256 and custodian identity.
- `receiptIncidentTransferCheckpointHash`: deterministic SHA-256 checkpoint commitment to 2–16 separately signed custodian attestations, independent of attestation array ordering.
- `verifyReceiptIncidentTransferCheckpointHistory`: independently replays **every original NEO-062 transfer receipt entry, NEO-061 signed transfer and NEO-060/059/058/... original archive proof** at every checkpoint. Verifies append-only original receipt-entry hash prefix, nondecreasing receipt count, unique checkpoint IDs, contiguous checkpoint sequence, signed predecessor hash and an externally retained authenticated checkpoint floor. Requires at least two distinct ACTIVE Ed25519 custodian signatures, distinct from NEO-061 archive-recipient and NEO-060 incident-checkpoint signing keys. Rejects forged/revoked/duplicated signers, cross-identity key reuse and silent historical key rotation.
- `inspectReceiptIncidentTransferCheckpointConflict`: verifies two incompatible Ed25519 signatures by the **same pinned trusted audit custodian key** for one checkpoint ID, namespace, sequence and predecessor; returns `RECEIPT_INCIDENT_TRANSFER_CHECKPOINT_CONFLICT_HOLD` and an order-invariant cryptographic evidence digest. Does not determine which branch reflects historical truth.
- Twenty-four regression tests cover valid single/two-checkpoint history; original archive-byte corruption and forged vault receipt; external rollback/fork pins; duplicate IDs, broken chains, forged, duplicated and revoked witnesses, role-key overlap, historical key continuity and authentic versus forged equivocation.

## Security scope and limitations
This is a **read-only cryptographic verifier**: no signatures are issued, no actual archiving or remote handoff is performed, no authenticated durable register is stored and no operational rights, releases, automatic review decisions or deployments occur. Distinct public keys are insufficient evidence of independent physical or organizational custody. Externally authenticated public-key rosters, complete source histories and monotonically retained trusted floor pins are mandatory prerequisites for practical anti-erasure guarantees.

A genesis floor cannot prove that other histories have not been deleted or substituted. Signed contradictory statements are forensic evidence only, not a basis for selecting a canonical external history. Current commitments depend on in-process JSON object serialization; an interoperable export protocol needs explicitly canonicalized bytes and an authenticated archive trust root.
