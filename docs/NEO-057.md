# NEO-057 — Incident transfer receipt succession and signed archive contradictions (DRAFT)

## Implemented
- `incidentTransferReceiptEntryHash`: domain-separated SHA-256 commitment to every verified transfer ID and digest, signed receipt list, independently pinned public-key identities, recipient roster, sequence, predecessor hash and incident-checkpoint position.
- `verifyIncidentTransferReceiptHistory`: verifies up to 64 sequential complete original NEO-056 evidence packages and signatures **from scratch** for each entry, including all nested NEO-055/054/053/... evidence. Rejects missing or forged source evidence, transfer-ID reuse, swapped namespaces, broken hash links, altered receipt entries, unreviewed historical recipient public-key changes, reassignment of an old archive key to a new identity, reductions in checkpoint height and rewritten checkpoint-hash or evidence-digest prefixes. A caller-supplied, separately secured `{count,head}` monotonic floor detects truncated and competing register histories.
- `inspectIncidentArchiveContradiction`: re-verifies both complete NEO-056 evidence packages and detects two incompatible signed transfer digests bearing the same transfer ID, namespace, recipient ID and Ed25519 public key. Returns `INCIDENT_ARCHIVE_CONTRADICTION_HOLD` with an order-invariant forensic SHA-256 digest. Identical statements, unrelated IDs, changed signers and forged receipts cannot establish this type of contradiction.
- Twenty-one regression tests cover complete histories, immutable register floors, duplicate transfers, prefix continuity, original archive tampering, forged receipts, recipient key continuity, identity/key reuse and genuine or forged conflict claims.

## Trust and safety boundaries
This is a **read-only verifier**, not a durable receipt store, delivery agent or external incident resolution system. A valid signature means one signing key endorsed a transfer digest; it does not prove physical receipt, storage, availability, legal authority or organizational independence. Monotonic register heads, trusted public keys, full source bytes and original evidence must be authenticated and retained outside this module. Deletion of a whole unpinned history cannot be detected from a genesis root alone.

The current protocol intentionally does not support recipient-key rotation or act as a cross-process replay ledger. JSON object serialization is the current local commitment format; independent systems require an explicit canonical byte format before interoperable archival verification can be claimed. Conflicting signatures are forensic evidence only, not a basis to decide which historical state was true or to grant access.

Every verification result returns `authorized:false`. GO-13 DRAFT / HOLD / DENY; no merge, deployment, key activation, release or operational archive writes.
