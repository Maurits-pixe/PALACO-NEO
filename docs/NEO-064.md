# NEO-064 — Dual-reviewed incident register for signed NEO-063 checkpoint conflicts (DRAFT)

## Implemented
- `receiptTransferConflictReviewPayload`: domain-separated Ed25519 OWNER/SECURITY statement binding namespace, unique incident ID, sequence, predecessor incident-register hash, original NEO-063 checkpoint ID and sequence, canonical checkpoint SHA-256, disputed witness identity, verified contradictory-claim digest, pinned NEO-027 policy digest, and the **only** allowed action `ESCALATE_RECEIPT_CHECKPOINT_CONFLICT_HOLD`.
- `receiptTransferConflictEntryHash`: stable domain-separated SHA-256 commitment to signed incident facts and two named reviewer statements.
- `verifyReceiptTransferConflictJournal`: fully replays the original NEO-063 checkpoint history and all NEO-062/061/060/... source evidence **for every incident**; binds the canonical signed claim, original audit-witness key and checkpoint hash to a previously verified checkpoint; independently verifies a contradictory statement signed by the same custodian using `inspectReceiptIncidentTransferCheckpointConflict`. Rejects forged or identical alternative assertions, missing or duplicated OWNER and SECURITY reviewers, revoked reviewers, duplicate incident IDs or equivocation fingerprints, fake SHA-256 commitments, untrusted policy pins, and truncation/fork relative to an authenticated externally retained incident floor.
- Twenty-one focused regression tests cover authentic independent signatures, original archive corruption, forged canonical and rival checkpoint statements, substituted public keys, repeated incidents, forbidden closure actions, forged OWNER signatures, revoked SECURITY reviewers, and external floor rollback/fork.

## Security and custody limits
This module **only verifies evidence**; it does not operate a durable incident database, issue signatures, notify OWNER/SECURITY, decide which external history is correct, close or release an incident, grant access, or deploy code. Physical and organizational independence is not established by distinct cryptographic keys alone. Full original histories, trusted reviewer and audit-witness keys, and an externally authenticated, monotonically retained `{count,head}` incident-register anchor must be maintained outside this verifier. Without such an anchor, wholesale history replacement or deletion is not independently detectable.

The only accepted case status is `ESCALATED_HOLD`; every result sets `authorized:false`. **GO-13 DRAFT / HOLD / DENY**: no merge, production rollout or operational release.
