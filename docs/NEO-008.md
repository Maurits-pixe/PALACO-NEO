# NEO-008 — Key transition and interruption reconciliation (DRAFT)

## Implemented
- A pure `proposeRegistryTransition` function supporting REVOKE and ROTATE proposals for an independently pinned NEO-007 registry snapshot.
- Rotation retains the old entry, marks it REVOKED and appends a distinct key entry. Revocation refuses to remove the final active key.
- `reconcileRegistryTransition` classifies exactly matching pre-write or approved proposed snapshots as NOT_COMMITTED or COMMITTED. All other states are HOLD.
- No success path grants authorization (`authorized:false`). The API does not write a registry or activate a new one.

## Trust & governance
The trusted previous and proposed pins must come from **authenticated independent custody**. If an adversary can rewrite both registry and pins, the reconciliation is meaningless. A prior pin and proposed pin alone do NOT establish authority to revoke or rotate. Mandatory human approval, dual control, signer identity validation, durable transaction handling, audit receipt retention and revocation distribution are outside the scope of this module.

Revoked keys are denied for historical verification under the conservative NEO-007 policy. Count-based validity windows remain an explicit limitation. Key registration and rollover MUST have external trust-policy checks. No cryptographic key material is generated or persisted by production code.
