# NEO-040 — Signed audit register for conflicting repair histories (DRAFT)

## Implemented
- `repairForkEvidenceDigest`: domain-separated SHA-256 fingerprint over the earliest signed divergence (height, common predecessor, both checkpoint heads, and matching witness identities). It canonicalizes left/right order and never accepts caller-provided verification verdicts.
- `repairConflictReviewPayload`: role-bound Ed25519 signing bytes for OWNER/SECURITY over the exact case ID, fork fingerprint, action, register sequence/predecessor, and independently pinned reviewer-policy digest.
- `repairConflictEntryHash`: immutable hash commitment to the complete pair of reviewer signatures and review statement.
- `verifyRepairConflictJournal`: re-verifies **both complete NEO-039 histories and their underlying NEO-038, NEO-037, NEO-036 original evidence**, requires one active OWNER and one active SECURITY with distinct keys, disallows duplicate cases and duplicate fork fingerprints, enforces a complete append-only hash chain and an externally retained rollback/fork floor.
- The only action is `ESCALATE_HOLD`. No `CLOSE`, `RELEASE`, `REVOKE`, or operational action exists.
- Eighteen regression tests exercise genuine two-branch conflicts, order independence, source-byte tampering, forged witness and reviewer signatures, missing roles, revoked reviewers, evidence substitution, duplicate incidents, rollback, fork, and silent closure attempts.

## Trust boundary
The register is a **read-only cryptographic verifier over caller-supplied data**. There is no durable log service, external trusted monotonic counter, immutable distributed witness log, archived review key history, trusted clock, proof of actual human identity, or automatic alert/escalation action. External callers must securely pin the original review policy, historical witness public keys, complete source evidence, and audit floor. A valid pair of signatures proves cryptographic statements, not human culpability or custody independence. Different valid competing branches indicate conflicting signed histories, not independently adjudicated wrongdoing.

Rollback and dropped-record detection are effective only against a separately authenticated previously known floor. Empty history with a genesis floor is structurally valid but never evidence of no past incident.

Every return is `authorized:false`. GO-13 HOLD/DENY. No merge to main, external writes, deployment, revocation, or live authorization.
