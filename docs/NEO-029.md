# NEO-029 — External quorum-policy activation CAS and crash reconciliation (DRAFT)

## Implemented
- `preparePolicyActivation`: revalidates the entire NEO-028 dual-reviewed succession chain against an independently retained chain floor, binds the last decision and policy hashes into a CAS request, and rejects an external active-policy pin that is not exactly the verified predecessor.
- `policyActivationPayload`: deterministic domain-separated Ed25519 bytes covering custodian, outcome, namespace, unique operation ID, policy change ID, decision head, old and proposed new policy pins.
- `verifyPolicyActivationReceipt`: checks a separately pinned active custodian key, trusted before-policy pin, expected operation ID, exact request, APPLIED outcome and canonical Ed25519 signature. Returns unsigned authority status (`authorized:false`) despite a valid assertion.
- `reconcilePolicyActivation`: re-verifies the ORIGINAL receipt itself and classifies independently observed external policy as NOT_COMMITTED, OBSERVED_COMMITTED or HOLD. A signed APPLIED assertion while the independent observed state is still BEFORE means HOLD, **never** automatic retry or automatic advancement.
- Seventeen new regression tests cover tampered signatures, policy versions, key status, replay, forked observations, crash windows and invalid inputs.

## Explicit trust and operational limits
This is a **verification-only/offline draft**. There is no external custodian connector, CAS executor, transaction log or independently maintained policy anchor inside PALACO-NEO. Operation IDs are compared against caller-supplied external expectations; there is no durable nonce-replay guard. The external custodian must provide authenticated atomic compare-and-swap, persistent single-use operation IDs, secure key custody, and a fresh independently verifiable post-write policy observation.

A signed APPLIED receipt proves only that the pinned custodian key signed an assertion, **not** that the external database durably committed it. `OBSERVED_COMMITTED` is still merely an assessment of supplied independent evidence. A caller that fabricates the external observation or trust pin can defeat this model; independent custody and a stronger audit trail are required before production. Human review, security approval and production authorization are separate gates.

No new reviewer is activated, no real external write, deployment or merge to main. Every return carries `authorized:false`; GO-13 HOLD / DENY.
