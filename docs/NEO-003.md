# NEO-003 — Checkpoint proposal and recovery guard (DRAFT)

## Implemented
- `INITIAL_ANCHOR` fixes the genesis reference.
- `recoverCheckpoint(records, trustedAnchor)` refuses invalid/edited/truncated records and invalid anchors.
- `proposeCheckpoint(records, trustedAnchor, event)` verifies current state then returns **only an immutable proposed** record set and new anchor.
- `reconcileCheckpoint(records, independentlyTrustedAnchor, proposedAnchor)` checks a proposed anchor matches a caller-provided independently trusted anchor.
- NEO-002 now rejects malformed hash types without exceptions.

## Explicit non-goals
**No actual atomic commits or persistence exist in this revision.** The functions do not lock, write files, control an OS, authenticate users, issue privileges, send data, or authorize execution. A self-generated checkpoint is not independent trust. A malicious actor controlling both records and anchor can substitute both. Race conditions and replay across processes are not solved.

## Future durable adapter requirements
An approved storage adapter must authenticate a trusted anchor, perform compare-and-swap under a serialized transaction, commit records and anchor together, fsync or use equivalent durability, recover from interrupted writes, and verify the trust boundary independently. It must retain GO-13 HOLD and execute/publish DENY until separately authorized.
