# NEO-012 — Local review-ledger transaction adapter (DRAFT)

## Implemented
- Exclusive local cooperative-writer lock via atomic directory creation.
- Under lock: independently supplied expected count/head is compared to the current verified review ledger.
- Proposed reviewed decision is structurally rechecked against the old ledger; temporary file write + fsync, atomic rename and directory sync are attempted.
- Read-only reconciliation classifies the old or new state, or refuses an unexplained state.
- No automatic removal of stale lock, no automatic retry, and no recovery by trusting the mutable file as its own anchor.

## Strong limitations
**This is an experimental single-host filesystem adapter, not an independently trusted custody provider.** The calling system must independently authenticate review signatures and the exact proposal through NEO-010 before calling this storage method. The adapter does not verify reviewer signatures or bind proposals to an external immutable approval token. A structurally valid forged ledger entry could be supplied by a malicious caller. Therefore: do not expose this adapter to untrusted callers or production.

A crash after rename can leave an uncertain outcome; reconcile against an independently captured before-position and proposal. A crash may leave a stale lock; remove it only after an operator verifies no live writer. An absent state file is indistinguishable from a deleted file without an external trusted anchor; non-genesis anchors fail closed. Filesystem semantics, symlink races, directory permissions, network filesystems, Windows durability and hostile processes are **not validated**.

No authorization, production deployment, identity capability, publication, or merge. GO-13 HOLD / DENY apply. Run `npm test` in Node >=20.
