# NEO-016 — Process-boundary crash simulations and directory continuity (DRAFT)

## Changes
- The review storage adapter now compares the filesystem directory's device/inode before and after reads, and before/after rename during a write. A detected change before rename is rejected. A detected change after rename is an uncertain commit requiring read-only reconciliation.
- Added three Linux/POSIX subprocess tests with an actual `SIGKILL` at controlled filesystem stages: before rename, after rename and manual lock recovery. They verify that a killed writer's stale lock is not stolen automatically and the separately pinned proposal is used to classify recovered state.
- NEO-015 CI run #73 completed successfully.

## Exact boundaries
The crash tests kill a **test-only subprocess that emulates the adapter's filesystem stages**, not the production adapter in the middle of its own write. These are not power-loss tests; the after-rename test does not prove disk durability or directory fsync behavior.

Directory identity checking is best-effort only: it does not eliminate path replacement between comparisons, attackers with write access to the parent, symlink swaps in path components, inode reuse or hostile concurrent processes. The adapter remains single-host and cooperative.

The operation still requires externally authenticated reviewer keys, roles, policy pin, ledger anchor and approval evidence. Every result contains `authorized:false`. No merge, production rollout, automatic stale-lock cleanup, key activation or authorization. GO-13 HOLD / DENY.
