# NEO-048 — Independently signed responsibility handoff checkpoint history (DRAFT)

## Implemented
- `handoffCheckpointPayload`: domain-separated Ed25519 signing statement binding namespace, unique checkpoint ID, sequence, preceding checkpoint digest, verified NEO-047 handoff count/head, NEO-046 quarantine count/head, pinned review policy digest, and witness ID.
- `handoffCheckpointHash`: deterministic SHA-256 commitment to full signed checkpoint and ordered witness signatures.
- `verifyHandoffCheckpointHistory`: re-verifies every original NEO-047 responsibility dossier, NEO-046 quarantine declaration, NEO-044 lifecycle and underlying original audit/replica evidence for every checkpoint. Requires 2–16 separately pinned ACTIVE witness identities with distinct Ed25519 keys, different from OWNER/SECURITY reviewer and successor keys. Rejects duplicate checkpoint IDs, forged or duplicate witnesses, key reuse across witness identities, unreviewed key changes for continuing witnesses, decreasing recorded handoff/quarantine counts, broken sequence/hash links and rollback/forks relative to an externally authenticated floor.
- `inspectHandoffWitnessConflict`: verifies two originally signed, mutually inconsistent statements of the same pinned witness key for the same checkpoint ID, namespace, sequence, predecessor and review-policy digest. Returns conflict evidence without determining which statement is true; rejects forged signatures or unrelated statements.
- Twenty-three regression tests cover valid one-/two-checkpoint histories, original byte tampering, signature forgery, key independence, revocation, replay, rollback and conflicting witness statements.

## Trust limits
The verifier creates no signatures, persists no journal, stores no key or identity, changes no permissions, executes no quarantine and activates no successor. Every source history, independent witness public-key roster and external monotonic checkpoint floor must be authenticated by the caller. A valid pair of signatures from different keys does not establish institutional/physical independence; conflicting statements by one signing key establish cryptographic inconsistency, not operator culpability. A separately trusted floor is required to detect deletion after process restart. Trusted-time and durable replay prevention remain external dependencies.

The checkpoint succession validates whole evidence snapshots and allows a repeated identical handoff tip; it does **not** claim a new handoff occurred at every checkpoint. The witness-conflict evidence helper checks signed assertions only and deliberately cannot establish truth of an alternate underlying handoff history. Actual responsibility/access transfer requires independent operational authorization and external registries.

Every outcome is `authorized:false`. GO-13 HOLD/DENY; no merge to main, execution, deployment or production access.
