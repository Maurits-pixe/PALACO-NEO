# NEO-005 — Uncertain-commit reconciliation (DRAFT)

NEO-005 introduces a pure classification function, `classifyUncertainCommit(records, before, proposed)`, to assess a read-back audit chain after an interrupted or uncertain file commit.

## Semantics
- `NOT_COMMITTED`: records exactly match the independently trusted pre-write anchor.
- `COMMITTED`: records match the previously captured proposed anchor, whose final record links to the pre-write head.
- `HOLD`: invalid inputs, corrupt chain, unlinked changes, or unexplained states.

All outcomes include `authorized:false`. This is **classification only**, not authorization or instructions to retry. A COMMITTED result must not by itself update a trusted external anchor; a separate trusted custody process and human review remain required.

## Mandatory trust inputs
The `before` and `proposed` anchors must be held separately from the mutable audit storage. The proposed anchor must have been captured before the uncertain write. This code does **not** implement independent custody, signature validation, fsync guarantees, or crash-safe updating of the external anchor. When that evidence is missing, the operator must stay on HOLD.

## Forthcoming boundaries
- Integrate a trusted anchor provider only after threat modeling and manual approval.
- Add platform-specific crash injection and filesystem fault tests.
- Never remove stale locks automatically.
- Keep GO-13 HOLD; execute and publish remain DENY.
