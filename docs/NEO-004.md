# NEO-004 — Single-host local checkpoint storage (DRAFT)

This module provides a **cooperative single-host** file adapter with mkdir-based exclusive lock, comparison against a caller-supplied trusted checkpoint, temporary file, flush, rename and directory sync. The implementation fails closed on unsupported directory sync, stale caller checkpoint, invalid records and existing locks.

## Security boundary

- **Not a database** and not a distributed transaction. No authority to execute or publish; GO-13 HOLD / DENY remain in NEO-001.
- **Trust anchor must be independent** of the checkpoint.json file. A caller that trusts the value returned by reading the file as its own anchor has no rollback or substitution protection.
- Lock coordination works for cooperating local writers sharing one filesystem, not untrusted actors, networked filesystems or arbitrary processes.
- A crash or error after rename but before directory sync may leave an **uncertain commit**. The API returns `IO_ERROR_OR_UNCERTAIN_COMMIT`; callers must reconcile with a separately trusted anchor before retry.
- The adapter does not bind an identity, sign receipts, authorize changes, provide backups, prevent malicious local write access or prove hardware-level durability.
- The trust boundary requires a protected directory; caller must control its permissions, parent path and physical environment.
- No lock-staleness auto-removal; operator intervention must verify there are no active writers.
- `inspectLocalCheckpoint` is read-only except normal filesystem reads. Tests operate on isolated temporary directories.
