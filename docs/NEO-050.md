# NEO-050 — Multi-custodian signed escalation checkpoint succession (DRAFT)

## Implemented
- `escalationCheckpointPayload`: domain-separated Ed25519 signing statement binds namespace, unique checkpoint ID, checkpoint sequence, prior checkpoint head, exact verified NEO-049 conflict escalation register count/head, pinned reviewer policy digest and individual audit custodian ID.
- `escalationCheckpointHash`: canonical SHA-256 commitment to the full checkpoint state and 2–16 custodian witness signatures, independent of witness array ordering.
- `verifyEscalationCheckpointHistory`: verifies **all complete original NEO-049 evidence** afresh for each checkpoint, including NEO-048 handoff checkpoints and NEO-047/046/044 originals. It requires a roster of 2–16 separately named ACTIVE custodian keys, refuses shared keys, forbids overlap with OWNER/SECURITY reviewer and disputed checkpoint-witness keys, and detects unsigned changes to existing custodian IDs. It checks monotonic escalation register extension (including pinned earlier prefix when a successor checkpoint advances its register position), checkpoint sequence/hash continuity, unique checkpoint IDs and independent externally retained `{count,head}` rollback/fork floor.
- `inspectEscalationCustodianConflict`: verifies two original signed contradictory state assertions from the **same pinned custodian key** at one checkpoint ID and trusted predecessor. Produces a SHA-256 forensic conflict fingerprint, always non-authorizing, without claiming either underlying external register state is true.
- Twenty-six regression tests cover positive and empty histories, consecutive checkpoints, signature-independent ordering, omitted records, forged signatures, reused keys and identities, revoked auditors, substituted source archive bytes, broken pins and contradictory independently verified signing statements.

## Trust boundaries
These functions are **read-only verification helpers**, not a durable database, networked custody protocol or operational escalation service. The caller supplies all complete historical evidence, previously trusted public keys and independently secured monotonic pins. Key diversity alone does not prove independent humans or physical custody. A valid contradictory pair of signatures proves key-level inconsistency, not which real-world history or organization is correct. An empty log with a genesis pin cannot establish that no prior records existed.

No review notification, case closure, incident release, key activation, credential minting, file write, merge or deployment is performed. No timestamps or off-box monotonic register are asserted. This verifier does not permit silently closing a conflict case: the only upstream NEO-049 action remains `ESCALATE_SIGNED_CONFLICT_HOLD`.

Every result contains `authorized:false`. GO-13 HOLD/DENY.
