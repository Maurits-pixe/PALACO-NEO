# NEO-060 — Independent signed incident register checkpoints (DRAFT)

## Implemented
- `receiptIncidentCheckpointPayload`: domain-separated Ed25519 signing statement binds namespace, unique checkpoint ID, checkpoint sequence, predecessor SHA-256, exact verified NEO-059 incident register position (count/head), and named audit custodian.
- `receiptIncidentCheckpointHash`: deterministic domain-separated SHA-256 commitment to the checkpoint scope and 2–16 independently signed attestations; witness ordering does not affect its hash.
- `verifyReceiptIncidentCheckpointHistory`: independently replays **every complete original NEO-059 incident record, all NEO-058 receipt checkpoints and the full NEO-057/056/055/... archive evidence** for each signed checkpoint. Checks monotonic source incident position and complete original incident hash prefix, unique checkpoint IDs, contiguous checkpoint sequence, signed predecessor hash, externally retained monotonic checkpoint-floor count/head, and 2–16 distinct ACTIVE Ed25519 signing keys. Rejects signing key reuse from OWNER/SECURITY reviewer keys, disputed or original NEO-058 checkpoint witness keys, duplicated signers, revoked witnesses, forged signatures, and unexplained historical key changes/reassignments.
- `inspectReceiptIncidentCheckpointConflict`: checks two correctly signed, incompatible incident-register positions from **one independently pinned audit custodian key** for the same checkpoint identity, sequence and predecessor. Returns an order-invariant evidence fingerprint and `RECEIPT_INCIDENT_CHECKPOINT_CONFLICT_HOLD` but never promotes either side to canonical authority.
- Twenty-four targeted regression cases exercise authentic single and successor checkpoints; complete source tampering (including original archive bytes and OWNER review signatures); missing, forged, duplicated, revoked and shared audit keys; replayed IDs, broken hash chains, external rollback/fork pins, unauthorised key changes, and genuine versus forged or identical competing signed checkpoint statements.

## Trust boundaries
This code is an **evidence-only verifier**. It does not independently obtain or store incident checkpoints, issue or distribute keys, deliver operational notifications, grant permissions, resolve/close cases, merge or deploy services. Distinct Ed25519 keys alone cannot prove real-world physical or organizational independence. All trusted rosters, full historical source evidence, and externally stored, authenticated monotonic `{count,head}` floors are the calling system's responsibility. Without such separately retained anchors, complete deletion/replacement of a supplied history is not independently detectable.

The verifier does not support silent key rotation. Valid conflict evidence proves that a signing key made incompatible assertions, not which historic state or off-box archive condition is correct. An empty checkpoint history with a genesis pin does not prove that no earlier history existed.

Every result includes `authorized:false`. **GO-13 DRAFT / HOLD / DENY**; no release, merge or production deployment.
