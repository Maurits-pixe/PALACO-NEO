# NEO-042 — Audit checkpoint succession and fork evidence (DRAFT)

## Implemented
- `verifyAuditCheckpointSuccession`: revalidates every full original NEO-041 multi-custodian checkpoint and the NEO-040 signed fork audit journal behind it. Each successive checkpoint must authenticate its previous **journal** count/head, while a separate domain-separated SHA-256 checkpoint succession chain records the signed seal and prior succession hash. Includes at most 64 checkpoints.
- Uniqueness of checkpoint IDs across supplied history; identity-to-Ed25519-key continuity for returning custodians; refusal to reuse a public key under a different custodian ID. Key rotation is held pending a separate signed rotation protocol.
- Trusted externally pinned checkpoint-succession floor `{count,head}` prevents truncation and conflicting prefixes. A floor at genesis is not an external proof of no prior records.
- `inspectAuditHistoryFork` fully verifies two branches before comparing chain commitments, distinguishes valid prefix extensions from different signed branches and produces `AUDIT_HISTORY_FORK_HOLD` for authenticated divergent histories.
- `auditHistoryEntryHash`: domain-separated ordered SHA-256 audit succession link binding sequence number, previous chain tip and signed seal digest.
- Nineteen new regression tests check valid one-/two-checkpoint histories, duplicate IDs, lost original evidence, key identity substitution, forged signatures, historical fork/truncation and conflicting valid branches.

## Trust boundary
NEO-042 remains strictly **read-only**, returning `authorized:false`. No automatic storage, network consensus, online witness service, key rotation, trusted timestamps, shared durable replay register, close/revoke/release action or production authorization is implemented. The caller must provide authenticated full historical evidence, separately pinned current public-key trust, and an independently retained monotonic succession floor. A successful signature proves only a key's statement, not physical or organizational custodian independence. Conflict detection can identify two contradictory, internally verified signed histories; attributing culpability or deciding the true canonical history requires independent adjudication.

NOTE: NEO-041 checks the complete journal against each anchor. NEO-042 verifies continuity between each successive journal position; it does **not** assert a new journal entry was added on every checkpoint, nor establish actual external writes. GO-13 HOLD / DENY; do not merge or deploy.
