# NEO-044 — Audit-custodian key lifecycle evidence (DRAFT)

## Implemented
- `verifyCustodianKeyLifecycle` replays the full NEO-042 audit history and all NEO-043 signed old/new custody key transitions, including independently pinned OWNER and SECURITY reviews. Every original NEO-040 fork audit entry, audit checkpoint, witness statement and proof byte remains part of the upstream re-verification.
- A cumulative lifecycle view follows active keys by custodian ID, marks replaced or absent keys as retired, and refuses a retired key returning as active on a later checkpoint. Historical key assignment to a different custodian ID is refused. The underlying NEO-043 verifier disallows unsanctioned rotation, missing old/new continuity signatures and duplicate rotation IDs.
- A domain-separated SHA-256 lifecycle digest commits the full checkpoint-history tip, ordered lifecycle transitions, retired key fingerprints, current active fingerprints and signed rotation IDs. An **optional externally retained exact pin** `{count,head,digest}` detects substitution when supplied by trustworthy independent storage.
- Fourteen regressions cover legitimate rotation, deterministic pins, forged signatures, rollback, missing reviews/rotation evidence, replayed IDs, original audit byte corruption and previously retired key reactivation.

## Security and governance boundary
The lifecycle representation is **immutable by cryptographic commitment**, not a durable immutable database. The code has no I/O, key registry writes, remote sync, trusted clock, authorization to rotate or revoke a key, or execution of repair or governance actions. External operators must securely retain history-floor and lifecycle pins, signing-key records, and original evidence. A key's cryptographic retirement in this view does not revoke it in any running service or HSM. It cannot establish whether private keys were compromised, and distinct signatures do not by themselves prove human authority or organizational independence.

For compatibility, `verifyAuditCheckpointSuccession` still accepts unrotated histories and its prior call signatures. NEO-044 adds an independent verification layer; it never silently changes a custody key.

Every result is `authorized:false`. GO-13 HOLD/DENY, no merge to main and no production activation.
