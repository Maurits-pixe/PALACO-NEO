# NEO-018 — Domain-separated Ed25519 recovery attestation (DRAFT)

## Added
- `recoveryAttestationPayload(namespace,challenge,signerId,receipt)`: canonical, domain-separated bytes containing the entire checked NEO-017 receipt, expected nonce, and signer identity.
- `verifyRecoveryAttestation(envelope,trust)`: read-only Ed25519 signature verification against an independently pinned witness public key, ACTIVE/REVOKED status, expected challenge and externally trusted pre-write checkpoint.
- Ten regression tests for signature forgery, key substitution, revoked signer, replay across challenges, digest tampering, identity binding and missing trust inputs.

## Critical boundary
This implementation **does not issue or persist challenges, sign records, manage signing keys or maintain a replay ledger**. Freshness and one-time consumption must be guaranteed by an authenticated external authority. An old signature will verify again if the same expected challenge is supplied. The public key, signer status and trusted before-position must be pinned outside the mutable workspace. The signature demonstrates possession of a private key, NOT that the witness genuinely observed the stored state; independently verifying the underlying records remains necessary.

The module cannot independently prove durable filesystem commits, real-world identity, reviewer authority, trusted time, network availability or consensus. All successful results contain `authorized:false`. No production integration, release, deployment or merge. GO-13 HOLD / authorization DENY remain active.

Run `npm test` on Node >=20; separate security review still required.
