# NEO-023 — Anchored CAS proof ledger and dual-observation classification (DRAFT)

## Implementation
- `verifyCASProofLedger(entries,trustedFloor?)` checks append-only SHA-256 linkage, unique operation IDs, contiguous external-anchor revisions/digests, and an independently pinned count/head floor.
- `proposeCASProofAppend(entries,trustedHead,plan,receipt,trust)` verifies a NEO-022 Ed25519 custodian receipt using separately trusted signer, operation ID and before-anchor. It proposes a new ledger entry linked to the verified predecessor; it **does not persist** that entry or update the external anchor.
- `compareCASProofObservations(first,second,trustedFloor)` treats observations as structurally STABLE only if both chains match and both extend the authenticated floor. Otherwise HOLD.

## Critical limitations
The proof entry contains a digest of the signed receipt, **not the complete independently re-verifiable receipt and trust provenance**. Historical entries can be checked structurally but their signatures cannot be reverified without the separately retained original signed receipt and trusted key history. Two identical reads do NOT prove two independent witnesses, disk durability, or cross-custodian consistency. Hashes do not authenticate an anchor by themselves.

No external API is called and no independent custody, persistence, consensus, global lock, issuance, merge, release or production deployment is performed. All outcomes remain `authorized:false`. GO-13 HOLD / DENY.

Run `npm test` under Node >=20, and require independent code/security review.
