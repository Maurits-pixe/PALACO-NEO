# NEO-011 — Review ledger recovery and cooperative conflict preflight (DRAFT)

## Added
- `classifyReviewRecovery(entries, before, proposal)`: compares a verified review ledger to a separately trusted pre-write count/head and a proposal captured before storage. Returns NOT_COMMITTED, COMMITTED or HOLD.
- `classifyReviewWritePreflight(entries, trustedBefore)`: checks whether the caller's current ledger matches the supplied externally trusted head/count before preparing a write.
- `REVIEW_INITIAL_POSITION`: defined genesis for empty review ledger.

## Trust and limitations
All results are `authorized:false`. These functions are **read-only classifications**. Preflight is not an atomic compare-and-swap and does not resolve concurrent writes; an approved storage provider must hold a lock or transaction across verification and persistence. The pre-write head and proposed record MUST be independently pinned and authenticated. A caller-provided untrusted head is insufficient for rollback protection.

This phase does not implement external custody, disk recovery, distributed locks, real approval issuance, reviewer identity authentication, or automatic replay. A COMMITTED classification does not authorize activation, merge, deployment, or release. Independent security review and platform-specific failure injection remain mandatory.
