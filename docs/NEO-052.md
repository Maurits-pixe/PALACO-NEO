# NEO-052 — Signed receipt succession and archive contradiction evidence (DRAFT)

## Implemented
- `verifyEscalationReceiptSuccession`: read-only verification of an ordered chain of up to 64 **complete NEO-051 original transfer bundles and signed archive receipt sets**. Each entry commits to the transfer ID, exact independently verified transfer digest, checkpoint count/head, previous chain hash, sorted signed receipt statements, recipient key fingerprints and the expected recipient roster. Every entry replays all underlying NEO-050 checkpoint and NEO-049/048/047/046/... historical evidence; caller-supplied prior verification verdicts are never trusted.
- Rejects duplicate transfer IDs, non-contiguous chain positions, SHA-256 commitment tampering, original-evidence replacement, decreasing checkpoint count, changed earlier checkpoint hashes **or evidence digests**, changes to a returning recipient's Ed25519 public key, and historical reuse of the same recipient key under another ID.
- Externally authenticated monotonic `{count,head}` receipt-register floor rejects truncation and conflicting prefixes. Genesis provides no proof of no earlier records.
- `inspectArchiveRecipientContradiction`: independently verifies two entire signed NEO-051 transfer packages with the **same transfer ID**, then checks whether the same recipient identity and pinned public key signed **different transfer digests**. Produces a deterministic conflict evidence digest and `ARCHIVE_RECIPIENT_CONTRADICTION_HOLD`; identical statements and unrelated transfers are not classified as conflict.
- Twenty-one regression tests cover valid one-/two-transfer histories, empty history HOLD, external pins, duplicate ID, broken chain, tampering, signature forgery, recipient key continuity and reuse, namespace changes, and verified/forged/repeated/conflicting archive statements.

## Boundaries
NEO-052 is a verification-only component: it signs nothing, writes no file or database, sends no network notifications, transfers no bytes, and grants no access, closure or release. Archive signatures verify a specific declaration about an evidence digest, **not durable physical custody, complete delivery or organizational independence**. An external authenticated, monotonically advanced receipt-register pin is essential for erasure resistance. No on-chain timestamps, operational replay registry, real-world identity proof or independent custody service is asserted.

The detector proves incompatible, correctly signed receipt statements from one signing key; it does not establish which claimed transfer was stored, whether anyone actually received the records, or the true external status. This phase deliberately does **not** implement recipient key rotation: an unexplained key change is a failure, not an implicit permission. All results are `authorized:false` and GO-13 remains HOLD/DENY. No merge or deployment.
