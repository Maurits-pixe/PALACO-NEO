# NEO-051 — Escalation evidence transfer and independently signed archive receipts (DRAFT)

## Implemented
- `escalationEvidenceManifest`: deterministic enumeration of the **complete, byte-represented NEO-050 checkpoint evidence objects**, with per-checkpoint SHA-256 evidence digests, ordered checkpoint IDs and hashes, total count and a domain-separated SHA-256 manifest digest. This helper creates a manifest and does not independently certify it.
- `escalationEvidenceTransferDigest`: domain-separated digest binds namespace, unique transfer ID, supplied externally trusted checkpoint floor, and the complete manifest.
- `escalationEvidenceReceiptPayload`: domain-separated Ed25519 recipient signature payload binds namespace, transfer ID, transfer digest and recipient identity.
- `verifyEscalationEvidenceTransfer`: first recomputes and compares the **entire manifest** against supplied original evidence records, rejecting missing, extra, reordered or changed checkpoint evidence; then re-verifies each NEO-050 checkpoint, all signed NEO-049 escalation and prior handoff/archive evidence, and independently pinned checkpoint floor. It requires 2–16 expected ACTIVE recipient IDs with separately pinned, distinct Ed25519 keys. Keys reused from the checkpoint custodians or the upstream review roster are rejected. It verifies every original receipt and an optional externally pinned exact transfer digest. Never creates signatures or sends evidence to a remote endpoint.
- Twenty-two regressions cover valid single-/multi-checkpoint transfers, deterministic manifest, original byte tampering, omission, insertion, reordering, policy and checkpoint-floor substitution, forged/replayed/omitted receipts, revoked recipients, key reuse and external pins.

## Security boundaries
This verifies **signed acknowledgments of a specified transfer digest**, not actual independent durable receipt or data availability. It neither stores nor transfers files, contacts recipient services, proves legal/organizational independence, confirms remote storage, supplies trusted time, nor creates an immutable database. The caller must securely retain trusted public keys, source byte representations, monotonic checkpoint floors and external transfer digest pins. JSON serialization is the specific local object-encoding commitment used here; any interoperable wire format or byte-level archival encoding requires a separately specified canonical encoding contract and corresponding validation.

Receipts must be collected out of band and remain subject to anti-replay controls in external custody systems. The transfer ID is unique only by convention absent a separately persisted replay register. Empty NEO-050 histories are intentionally refused for evidence transfer. Passing verification never grants access, deletes source data, releases disputes or asserts physical custody.

All outcomes set `authorized:false` and retain GO-13 HOLD/DENY. No merge, deployment or operational archival writes.
